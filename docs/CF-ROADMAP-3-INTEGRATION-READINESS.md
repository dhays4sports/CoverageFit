## 3. Demonstrated producer-attention gap and smallest correction

**Blocker R1 — selection precedes ranking.** `producer-intelligence-local.page` chooses UCP links by opportunity ID and limit. Only those records reach `compareAttention`. Thus C4's recommended order is meaningful within a page, not across the workspace. The new real file-backed test admits/evaluates 25 earlier-ID nonurgent prospects and a later `zzz-urgent` customer CALL. Its stored result is CURRENT and human eligible; initial Today is empty; the next service page contains the CALL. `commandCenterPreview` additionally discards that service cursor. Existing UI page labels are honest but cannot make this a complete producer work queue.

**Smallest existing-architecture solution — designed, not implemented:** materialize only the existing Attention selection tuple beside the C2 current-result pointer (prefer columns on its one-row-per-prospect queue; do not create another score/profile service). Persist decision ID, generation, evidence/context/identity versions, existing rank/band, human eligibility, due sort key, validity boundary and projection build. Update atomically with successful fenced C2 acknowledgment. Admission, context/identity/safety changes, retraction and failure must invalidate the candidate in their governed mutations; no GET refresh. Retain C3 as the final freshness/safety check.

Use a workspace/scope-filtered indexed keyset selection matching `compareAttention` (eligibility, rank descending, due ascending, stable ID), restricted to relevant open producer work. Reuse source-backed C4 bands; do not map CALL to contact permission. Material context or queue-generation changes invalidate cached rank even without an evidence revision change. Preserve C3's explicit future-timer-only generation exception until its validity boundary; scheduling that timer must not prematurely hide a still-current handoff. Time-boundary predicates with controlled now remove expired candidates before display; C2 due work performs reevaluation independently. Cached CURRENT is never a permanent truth flag.

Read a bounded candidate window, validate C3 only for those candidates, and return a continuation plus coverage/lag information when the scan budget is exhausted. Do not loop through the whole population to fill one page. Dirty/failed/held records are separate exception coverage, never stale fallback. Define ordering as current among evaluated, valid candidates; outstanding evaluation lag prevents a claim of complete real-time prioritization. Existing UI must propagate continuation/coverage, and refresh the first page when ranks change; keyset pagination across concurrent reprioritization is not a frozen snapshot. One governed, resumable initial backfill is allowed only in an independently authorized environment, never a request-side population scan.

Future acceptance: late-ID urgent item appears first among thousands; bounded query plan and candidate count; owner/STOP/time/revision races invalidate immediately; crash/ack cannot publish old rank; filtered/empty pages preserve continuation; equal-rank paging is deterministic; newer high-priority work cannot be hidden indefinitely by an old cursor; all execution flags remain false. This is the smallest remaining functional correction before global Today dogfood. It was deliberately not implemented during this consolidation mandate.

## 4. Hosted-adapter readiness

**Blocker R2 — no accepted D1 adapter.** Current C4 deliberately accepts `LOCAL_SYNTHETIC` + `SQLITE_READ_TRANSACTION` only and rejects D1 labels. The authorizer and adapter are trusted server dependencies, not security proven by a string or client-provided workspace. Existing production auth is a producer token with server-configured workspace/actor; multi-tenant roles and record membership must be independently mapped before hosted C4. Query predicates must enforce both tenant and record scope. Cursors/bookmarks never grant scope. Preserve private/no-store responses and reauthorize every page/detail.

Cloudflare's [D1 database API](https://developers.cloudflare.com/d1/worker-api/d1-database/) describes transactional `batch()` and sequentially consistent sessions. [`first-primary`](https://developers.cloudflare.com/d1/best-practices/read-replication/) starts with primary freshness; a bookmark establishes a minimum database version. **Inference for this contract:** sequential consistency alone does not establish the single stable multi-query snapshot required by local C3. Use a demonstrated bounded transactional read batch or single relational read containing all freshness inputs; alternatively a rigorously fenced bounded retry that fails unavailable on change. A naive sequence of awaited reads can combine evidence/context/queue versions. Do not transplant local `BEGIN`, savepoints or synchronous `.get/.all` as a D1 adapter.

**Blocker R3 — local SQL portability/budget.** The new SQLite probe measures **583 prepared-statement executions for 25 one-event CURRENT prospects**, including schema checks and C3's two historical/current projections. A 100-record allowlist creates **103 bindings** (workspace, cursor, IDs, limit). D1 currently documents [100 parameters/query and 50 Free / 1,000 Paid queries/invocation](https://developers.cloudflare.com/d1/platform/limits/). These are observed local algorithm costs, not D1 network measurements; a statement-for-statement port is unsuitable. Budget the full request and page under actual plan limits, bulk-hydrate selected IDs in bounded reads, and use scoped membership joins or bounded authorization batches within parameter limits. Per-prospect history remains unbounded; cap/hydrate with explicit unavailable/continuation behavior rather than silently truncating evidence. No plan upgrade or spending is proposed.

Missing binding/schema/version, corrupt JSON, unavailable primary, timeout or inconsistent state must yield UNAVAILABLE/503 without legacy fallback or repair writes. Future tests must interleave evidence/context/owner changes between reads, verify tenant predicates, lease/time boundaries, canonical hashes, row/query budgets and zero read mutations. Offline SQLite tests and static graph checks cannot prove D1 sessions, replication, bindings or account behavior. No hosted adapter, migration, worker or flag is activated here.

## 6. Minimum authorized dogfood and measurement contract

The smallest useful real exercise is **read-only producer assistance using a small expressly approved existing-record cohort**, with AgencyZoom retaining cadence/stage ownership. It need not wait for CoverageFit automated messaging or a RingCentral canary if all contacts continue through independently authorized existing manual workflows. It does require correct globally bounded attention (or an explicitly complete fixed cohort without a global claim), proven deployment/auth/source boundaries, current suppression/ownership/identity evidence, source-use/retention approval, accurate latest event ingestion and a manual fallback. None of those approvals or real records is obtained/used here.

Reuse `cf_evidence_decisions`, `cf_evaluation_results`, `cf_solo_activity`, `cf_opportunity_effort`, existing acquisition attribution/cohort records, recommendation revisions and actual policy evidence. Do not add another analytics platform. Minimum logical measurement envelope, **specified but not wired**: workspace/prospect/cohort/source, decision/profile/context/generation versions, shown-at/current status, action/reason/evidence refs, producer disposition (accept/override/dismiss with reason), actual observed outcome + independent evidence reference/time/verifier, effort entries and correction references. Stable scoped event/request IDs deduplicate; corrections append/supersede; retention/deletion governs derived measurements. A decision reference erased for privacy becomes unavailable, not reconstructed from retained private content.

| Measure | Operational definition and required evidence |
|---|---|
| Producer minutes per useful conversation | All attributable triage, lookup/context switching, review/correction, conversation, follow-up, administration and exception minutes divided by independently verified two-way useful conversation episodes. Freeze episode dedupe and window before enrollment; zero conversations gives undefined, never zero. Report missing effort and coverage; no complete-cost claim from partial logging. |
| Qualified conversations per 100 leads | 100 × distinct enrolled prospects with a verified useful two-way conversation AND documented need/intent/timing plus a justified next step / fixed distinct enrolled lead denominator. Retain held/no-response records in the enrollment denominator; separately disclose pre-enrollment ineligibility, source, age and duplicate exclusions. No post-hoc denominator pruning. |
| Avoided repetitive questions | Audit a bounded set of question opportunities against facts reliably known at that decision time. Count a specifically documented planned question suppressed because it was already answered; report audited opportunities and actual redundant questions separately. An inference that a question might have been asked is not a verified saving. |
| Quote-ready opportunities | Unique prospects with a producer-verified line-specific readiness checklist and evidence, timestamp and decision reference. QUOTE PREPARATION recommendation or CRM stage alone is insufficient. |
| Verified quote/bind outcomes | Unique actual quote/version references and separately verified bound policy/term-premium evidence. Revisions are not extra quotes; proposed coverage/premium, simulated replies, CALL, sent texts and pending binds are not written premium. Report missing evidence separately. |
| Unnecessary producer interruptions | Unique displayed handoffs independently marked duplicate, already handled, unjustified, mistimed or prohibited / all displayed handoffs, plus actual review/correction minutes and cause. Count repeated exposures separately from unique decisions to reveal attention burden. |

**Measurement gap R4:** existing `acquisition-measurement.mjs` can mark `qualified` from score/route/stage or wrap activity. That is not the verified qualified-conversation numerator above. Existing effort entries are integer minutes (1–480) in broad categories; no entry means unmeasured, not zero, and sub-minute review cannot be faithfully recorded per click. Existing C2 traces do not persist producer acceptance/override/exposure by themselves. Use an approved minimal session-level tally and source-linked outcome disposition, then map to existing governed records; implement any missing narrow capture only after workflow approval. Do not silently relabel legacy economics or claim that the measurement envelope is implemented.

One low-friction session can record duration, useful outcomes and corrections at the end, with prefilled decision refs and a short exception reason. Include the time spent measuring. Preserve historical CONTROL, TEST exclusion and the existing seven-day fresh-lead policy where applicable. Agree cohort/window, baseline source/age/channel comparability, qualification rubric and review sample in the same eventual dogfood approval. Early samples are descriptive, not causal uplift. Stop on wrong-identity disclosure, suppression/owner leakage, false current action or unauthorized execution; use the existing manual agency workflow. All business metrics currently remain **UNMEASURED**.
